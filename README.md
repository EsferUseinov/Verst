# Verst – VR/AR лабораторні роботи

Навчальний Unity-проєкт для курсу "Розроблення VR/AR застосунків".

## Про проєкт

Дія відбувається у віртуальному виробничому цеху зі складом, верстатами, складальним столом, зоною контролю якості та відвантаженням. Проєкт задуманий як легка крафтова гра, а не точний симулятор виробництва: головна механіка – створення нових предметів з наявних. Гравець бере деталі, розкладає їх на робочій станції й отримує з них новий предмет за рецептом.
Предмети навмисно стилізовані: масивні, легкі, їх зручно брати й переносити – у пріоритеті ігровий досвід, а не реалізм.

Крафт має мету. Цех постачає загін, який воює на макеті поля бою поруч із палетою відвантаження. Готові вироби відправляються на палету і посилюють загін у наступній хвилі, причому кожен виріб дає своє посилення. Гра повністю працює офлайн.

## Ігровий цикл

| Виріб | Ефект на одну хвилю | Проти кого |
|---|---|---|
| Привід | +2 бійці | рій |
| Редуктор | броня загону | стрільці |
| Манометр | пробиття броні | броньовані |

Обмеження задає сировина. На старті її 6 одиниць, після кожної хвилі приходить ще 4, але більше 6 на складі не вміщається. Заготовка, пруток і лист коштують по одиниці, болти безкоштовні. Склад наступної хвилі видно на табло заздалегідь, тож гравець вирішує, що з обмеженої сировини зробити саме під неї. Готові вироби можна накопичувати про запас.

Гра складається з 5 хвиль і 3 життів. Програна хвиля забирає життя, після чого гра переходить до наступної хвилі. Повторне натискання кнопки під час бою одразу дораховує його результат. Параметри бійців, сила ефектів і склад хвиль налаштовуються в `Assets/_Project/Data/Battle/BattleConfig.asset`.

## Мок-сервер (Лаб. 5)

Локальний сервер імітує сервер цеху. Він віддає показники датчиків верстатів і приймає звіти про проходження візарду «Перша зміна». Гра без нього працює, мережеві вкладки просто показують помилку з'єднання.

Запуск з кореня проєкту:

```
python Tools/MockServer/server.py
```

Параметр `--port` змінює порт (за замовчуванням 8080), `--delay 2` затримує кожну відповідь на 2 секунди, щоб було видно стан завантаження.

| Запит | Що робить |
|---|---|
| `GET /api/sensors` | температура, оберти, навантаження і статус верстатів `machine_1` та `machine_2` |
| `POST /api/reports` | приймає звіт візарду (ID оператора, час, помилки, відповіді по кроках) і повертає номер звіту |

Приклад відповіді `GET /api/sensors`:

```json
{
  "updatedAt": "2026-11-23T14:05:26+00:00",
  "machines": [
    { "id": "machine_1", "name": "Верстат 1 (обробка)", "temperature": 67.2, "rpm": 773, "load": 0.57, "status": "ok" }
  ]
}
```

Отримані звіти зберігаються в `Tools/MockServer/reports/`, ця папка не потрапляє в Git. Адреса сервера для Unity задається в `Assets/_Project/Data/Network/Api_Local.asset`. Оскільки сервер працює по HTTP без шифрування, у Player Settings дозволено завантаження по HTTP.

## Структура гілок

- `main` – стабільна гілка, містить змерджені готові лабораторні роботи.
- `lab-1`, `lab-2`, ... – робочі гілки для кожної окремої лабораторної роботи.
  Після завершення роботи гілка мерджиться в `main`.

## Лабораторні роботи

1. **Лаб. 1** – Знайомство з Unity: 3D-сцена, префаби, скрипти та фізика колізій.
2. **Лаб. 2** – VR-сцена: пересування в просторі та маніпуляція об'єктами.
3. **Лаб. 3** – Просторові інтерфейси (Spatial UI) та покрокові форми.
4. **Лаб. 4** – Природні взаємодії руками (Hand Tracking).
5. **Лаб. 5** – Взаємодія з серверами: REST API та телеметрія.
6. **Лаб. 6** – Багатокористувацький режим (Photon) або Змішана реальність (Mixed Reality).

## Середовище

- Unity 6 LTS, Universal Render Pipeline (URP)
- Android Build Support (для збірок під Meta Quest)
- Meta XR All-in-One SDK (через Unity OpenXR Plugin, з Лаб. 2)
- Python 3 для мок-сервера (лише стандартна бібліотека, з Лаб. 5)
